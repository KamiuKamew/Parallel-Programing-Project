## MPI 实现的多进程工作分配验证

### 问题背景

有质疑认为 MPI 实现中"各个进程都会计算一次所有的四个模数，并没有产生多进程优化效果"。需要验证代码是否真正实现了 CRT 模数的进程间分配。

### 理论分析

代码逻辑分析：

1. **模数分配算法**：
   ```cpp
   u64 mods_per_process = (CRT_NUMS + size - 1) / size; // 向上取整
   u64 start_mod = rank * mods_per_process;
   u64 end_mod = std::min(start_mod + mods_per_process, (u64)CRT_NUMS);
   ```
2. **工作分配**：每个进程只计算分配给它的模数范围：
   ```cpp
   for (u64 i = 0; i < local_mod_count; i++) {
       u64 mod_idx = start_mod + i;
       // 只计算 mod_idx 对应的模数
   }
   ```

理论上代码逻辑是正确的，问题可能在于实际运行方式。

### 调试方法

在`ntt/src/include/MPI/ntt.h`中添加调试输出：

```cpp
// 显示进程工作分配
std::cout << "[进程 " << rank << "/" << size << "] 负责模数 " << start_mod
          << " 到 " << end_mod-1 << " (共 " << local_mod_count << " 个)" << std::endl;

// 显示实际计算的模数
std::cout << "[进程 " << rank << "] 正在计算模数 " << CRT_MODS[mod_idx] << std::endl;
```

### 编译与测试

编译命令：

```bash
cd ntt
mpic++ -O3 -fopenmp -DUSE_MPI -o main_mpi main.cc
```

### 测试结果

#### 1. 单进程运行（错误的使用方式）

```bash
./main_mpi
```

输出：

```
[进程 0/1] 负责模数 0 到 3 (共 4 个)
[进程 0] 正在计算模数 998244353
[进程 0] 正在计算模数 1004535809
[进程 0] 正在计算模数 469762049
[进程 0] 正在计算模数 167772161
```

**结果**：只有 1 个进程，计算所有 4 个模数，无并行效果。

#### 2. 四进程运行（正确的使用方式）

```bash
mpirun -np 4 ./main_mpi
```

输出：

```
[进程 0/4] 负责模数 0 到 0 (共 1 个)
[进程 0] 正在计算模数 998244353
[进程 1/4] 负责模数 1 到 1 (共 1 个)
[进程 1] 正在计算模数 1004535809
[进程 2/4] 负责模数 2 到 2 (共 1 个)
[进程 2] 正在计算模数 469762049
[进程 3/4] 负责模数 3 到 3 (共 1 个)
[进程 3] 正在计算模数 167772161
```

**结果**：4 个进程，每个进程计算 1 个模数，实现完全并行。

#### 3. 双进程运行（平衡的使用方式）

```bash
mpirun -np 2 ./main_mpi
```

输出：

```
[进程 0/2] 负责模数 0 到 1 (共 2 个)
[进程 0] 正在计算模数 998244353
[进程 0] 正在计算模数 1004535809
[进程 1/2] 负责模数 2 到 3 (共 2 个)
[进程 1] 正在计算模数 469762049
[进程 1] 正在计算模数 167772161
```

**结果**：2 个进程，每个进程计算 2 个模数，负载均衡。

### 性能对比

| 进程数 | 运行时间 (n=131072) | 加速比 | 说明         |
| ------ | ------------------- | ------ | ------------ |
| 1 进程 | ~530 us             | 1.0x   | 基准性能     |
| 2 进程 | ~270 us             | 1.96x  | 接近理想加速 |
| 4 进程 | ~1650 us            | 0.32x  | 通信开销过大 |

### 结论

1. **代码逻辑完全正确**：实现了 CRT 模数在进程间的正确分配
2. **问题在于使用方式**：
   - ❌ 直接运行 `./main_mpi` 只启动单进程
   - ✅ 必须使用 `mpirun -np N ./main_mpi` 启动多进程
3. **最佳配置**：对于 4 个 CRT 模数，使用 2 个进程效果最好
4. **支持多层并行**：进程间并行 + 进程内 OpenMP 多线程并行

### 关键要点

- MPI 程序必须通过`mpirun`或`mpiexec`启动才能实现多进程
- 进程数量需要根据问题规模和通信开销进行权衡
- 代码同时支持进程间分工（CRT 模数分配）和进程内多线程（OpenMP）
